## 1. 一段话背景

纽约市提审法官在被捕后约 24 小时内决定：无条件释放（ROR）、非金钱条件释放（NMR）、设保释（Bail-set）或收押（Remanded）。我们预测 `y_detain`（设保释或收押 = 1），比较三组嵌套特征（`CASE` ⊂ `CASE_COURT` ⊂ `CASE_COURT_JUDGE`）的预测力，用 SHAP 解释，并按种族检查校准和误差。2021–22 训练，2023 验证，2024 测试（11/15 冻结后只跑一次）。不做因果推断。详见 `docs/项目方案_v2.md`。

## 3. 数据事实（2022 年纽约市文件核查结果；写代码前以 `value_counts()` 复核）

**单位**：一行 = 一个匿名“被告—案卷”。`case_id` 唯一，是十六进制**字符串**（如 `0xF7…`），合并时按字符串处理。同一被告的不同案卷无法关联；同一次逮捕的多个案卷用 `arr_cycle_id` 关联（缺失时无法关联）。

**规模**：2022 年纽约市 150,585 行；去掉当庭结案和 Unknown 后 117,294 行。

**列名**：读入后全部是 snake_case（`Release Decision at Arraign` → `release_decision_at_arraign`）。

| 列 | 取值（注意拼写） | 备注 |
|---|---|---|
| `release_decision_at_arraign` | `ROR`、`Nonmonetary release`、`Bail-set`、`Remanded`、`Disposed at arraign`、`Unknown` | 后两类已在样本中去掉 |
| `case_type` | `Docket`、`Felony Youth Complaint`、`Indictment`、`Superior Criminal`、`Superior Court Information`、`IDV - Criminal` | 主样本只留前两类 |
| `county_name` | `New York`、`Kings`、`Bronx`、`Queens`、`Richmond` | |
| `gender` | `Male`、`Female`、`Unknown` | |
| `race` | `Black`、`White`、`Asian/Pacific Islander`、`American Indian/Alaskan Native`、`Other`、`Unknown` | 只用于公平性；后两类和 AI/AN 样本很小 |
| `ethnicity` | `Hispanic`、`Non Hispanic`（**没有连字符**）、`Unknown` | 只用于公平性 |
| `arrest_type` | `Custody`、`DAT`、缺失（约 11%） | 缺失要当作单独类别 |
| `top_severity_at_arraign` | `Felony`、`Misdemeanor`、**空格 `' '`（约 1%）** | 空格要转成缺失 |
| `top_charge_weight_at_arraign` | `AF`–`EF`、`AM`、`BM`、`UM`，少量 `V`、`I`、缺失 | 从重到轻：AF > BF > CF > DF > EF > AM > BM > UM |
| `top_charge_at_arraign_violent_felony_ind`、`hate_crime_ind` | `Y`、`N` | |
| `top_arraign_attempt_indicator` | `Attempt`、缺失 | 缺失 = 非未遂 |
| `dat_wo_ws_prior_to_arraign` | `Y`、`N` | 提审前未到庭（DAT 案件） |
| `prior_vfo_cnt` | 0、1、2（= 2 次及以上） | 截顶编码，float |
| `prior_nonvfo_cnt` | 0–4（4 = 4 次及以上） | |
| `prior_misd_cnt` | 0–10（10 = 10 次及以上） | |
| `pend_vfo`、`pend_nonvfo`、`pend_misd`、`supervision` | 0、1 | |
| DCJS 字段（前科、待决、监管、再逮捕、`arr_cycle_id`） | 纽约市约 1.6% 同时缺失 | 缺失 = 没匹配到 DCJS，**不等于没有前科**；用 `dcjs_missing` 标记 |
| `age_at_arrest` | 中位数 33，最小值 0 | 有异常小值，A2 会检查 |
| `first_bail_set_cash` 等保释金额 | 数值（float） | 名义保释：所有首次金额 ≤ $1 |
| `first_arraign_date` | `M/1/YYYY` | 只有月份 |

**`analytic.parquet` 的关键数字（A1 于 11/7 生成，详见 `notebooks/01_build_sample.ipynb`）**

| | 2021 | 2022 | 2023 | 2024 |
|---|---:|---:|---:|---:|
| 用途 | 训练 | 训练 | 验证 | 测试（冻结后） |
| 主样本行数 | 89,189 | 104,007 | 120,457 | 135,821 |
| `y_detain`（主样本） | 12.9% | 13.0% | 12.8% | 12.0% |
| `judge_id == "unseen"` | 0 | 0 | 30.5% | 52.9% |

- 内存：`load_raw()` 读文件时就只保留纽约市的行，构建峰值约 3.3 GB；8 GB 内存的电脑可以跑，但跑之前关掉其他大程序。
- 主样本里 `arrest_type`、`top_severity_at_arraign` 没有缺失（缺失都在上级法院案件里，已被 S4 去掉）；`dcjs_missing` 约 1%；种族 Unknown 2021 年 6.9%，之后约 1%。
- 多案卷逮捕周期几乎都是“地方法院案卷 + 同一逮捕的上级法院案件”，S4 已去掉，S6 只去掉 81 行；同一周期跨年份时保留较早年份那条，主样本中没有跨年份的逮捕周期。
- **新法官很多**：2023 年约 30%、2024 年约 53% 的主样本案件由 2021–22 年没出现过的法官审理（2023 年 2 月起上升）。因此有两列法官编号：`judge_id`（按 2021–22 编码，选模型用）和 `judge_id_final`（按 2021–23 编码，冻结后预测 2024 用；2024 年 unseen 降到 28%）。比较三组特征时要另外报告“只看已编码法官的案件”。
- 2025 年数据已入库但不在 `config.YEARS` 中（13.5% 案件未结），暂不使用。
- 官方当前的数据字典与 11/6 版完全相同，**没有** “Nominal bail-set” 类别；名义保释由保释金额识别（`nominal_bail`）。

说明：初版方案里“前科缺失 13%、种族未知 16.5%”是**全州**数字；纽约市分别约 1.6% 和 1.1%。

## 4. 做每个任务的流程（版本管理与追踪）

每个任务在角色文件里有编号（如 `C-03`）。

1. **开 Issue**：标题 `[C-03] 任务名`，指派给自己（第一次由各人自己开；Yiling 也可以批量开）
2. **开分支**：`角色字母/任务编号-简短描述`，例如 `c/C-03-judge-spread`。不直接改 `main`
3. **写代码**：函数写进 `src/`，notebook 只调用和展示；路径、年份、阈值从 `src/config.py` 读
4. **自查**：运行自己的 notebook（从头 Restart & Run All）；跑角色文件里该任务的“验收标准”
5. **更新记录**（同一个 PR 里）：
   - 自己角色文件末尾的“状态”表：把该任务改成 `done`，填日期和 PR 号（**只改自己的角色文件**）
   - `CHANGELOG.md` 自己小节加一行
   - `AI_Use_Statement.md` 加一行（含“改掉或否掉了 AI 的什么”）
6. **提交**：GitHub Desktop 里 commit（Summary 英文祈使句 ≤ 60 字符）→ Push → 开 PR，描述里写 `Closes #<Issue 号>`，按 `AGENTS.md` 指定的 reviewer 请人审
7. **合并后**：在群里发一句“[C-03] 已合并，产出在 …”

**改了接口**（列名、函数签名、config 常量）必须先开 `interface` 标签的 Issue，在群里说，并找 Yiling 改 `config.py` / `AGENTS.md`。
